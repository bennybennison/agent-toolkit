# Skill: Idea Exploration

Use this when a request is still a rough idea and the right next step is exploration, not specification or implementation.

## Goal

Produce an `IdeaBrief` that captures:

- what the idea is
- who it helps
- the most important use cases
- open questions
- risks and edge cases
- plausible directions
- whether to proceed now, later, or not yet

Use the template in `templates/workflows/IDEA_BRIEF.md` when creating the artifact.

## When To Use

- early product or feature thinking
- requests with multiple possible directions
- ideas that may not belong in the repo yet
- concepts that need stress-testing before planning

## Process

1. State the core idea in one sentence
2. Identify the user or operator who benefits
3. List the concrete use cases or jobs-to-be-done
4. Surface the unknowns blocking a confident plan
5. Explore alternatives and adjacent variants
6. Capture risks, edge cases, and likely constraints
7. End with a recommendation:
   - proceed to mapping
   - proceed to feature spec
   - defer
   - reject for now

## Output

Create an `IdeaBrief` with:

- idea summary
- user value
- key use cases
- open questions
- alternatives considered
- risks and unknowns
- recommendation

## Anti-Patterns

- Jumping straight to implementation details
- Turning every idea into a spec before the use case is clear
- Treating backlog capture as equivalent to exploration
- Hiding uncertainty instead of naming it
